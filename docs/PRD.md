# 技能树养成应用 PRD（产品需求文档）

## 1. 产品概述

### 1.1 产品名称

技能树养成（Skill Tree）

### 1.2 产品定位

一款以「技能树可视化 + 每日打卡」为核心机制的前后端分离网页应用，帮助用户通过持续学习、量化追踪的方式养成技能学习习惯，逐步从入门走向精通。

### 1.3 核心价值

- **可视化成长**：以进度条直观展示每个技能的成长阶段，让学习成果可量化、可追踪
- **每日打卡机制**：通过每晚固定时间窗口打卡，培养持续学习习惯
- **惩罚与激励并存**：未打卡扣除进度，激励持续学习；每日上限 8 小时防止突击刷量
- **心得沉淀**：以文字/图片记录每日收获，支持标签筛选与多维度时间视图
- **苹果风设计**：前端采用 Apple Design 风格，强调简洁、留白、毛玻璃质感与流畅动效

## 2. 目标用户

| 用户画像 | 特征描述 |
|---------|---------|
| 自学者 | 正在学习一门或多门技能，需要追踪学习进度 |
| 在职学习者 | 业余时间充电，希望量化成长过程 |
| 学生群体 | 有明确学习计划，需要打卡激励机制 |

## 3. 功能需求总览

应用包含两大核心模块：

| 模块 | 核心能力 |
|------|---------|
| 技能树 | 创建技能、进度条可视化、阶段等级、学习时长累计与衰减 |
| 每日收获 | 时间窗口打卡、多技能进度录入、心得记录（文字/图片）、标签管理、标签筛选、日/周/月视图 |

## 4. 模块一：技能树

### 4.1 技能创建

| 需求项 | 说明 |
|--------|------|
| 创建方式 | 用户输入技能名称，生成该技能的学习进度条 |
| 必填字段 | 技能名称 |
| 可选字段 | 技能描述、技能图标/颜色（便于区分） |
| 唯一性约束 | 同一用户下技能名称不可重复 |
| 数量限制 | 暂不设上限，后续可加合理限制 |

### 4.2 进度阶段定义

技能学习进度按累计学习小时数划分五个阶段：

| 阶段 | 累计小时数 | 阶段说明 |
|------|-----------|---------|
| 未入门 | 0 ~ 30h | 刚创建，尚未积累足够时长 |
| 入门 | 30h | 掌握基础知识，对技能有基本认知 |
| 小成 | 100h | 能够独立完成基础任务 |
| 熟练 | 300h | 能够流畅应用，处理复杂场景 |
| 精通 | 600h | 深入理解，可指导他人 |

**进度条展示规则**：
- 进度条以「当前阶段→下一阶段」为目标展示进度
- 到达精通后进度条显示为满格（已完成）
- 进度条上方显示当前累计小时数与所处阶段名称

### 4.3 每日学习录入规则

| 规则项 | 说明 |
|--------|------|
| 录入时间 | 通过「每日收获」模块统一录入（详见模块二），技能树本身只做展示 |
| 单日上限 | 单日所有技能学习小时数总和不超过 **8 小时** |
| 累计方式 | 每日录入的小时数累加到对应技能的累计小时数中 |
| 精度要求 | 支持小数，最小精度 0.5 小时（半小时） |

### 4.4 进度衰减机制

| 规则项 | 说明 |
|--------|------|
| 衰减触发 | 当日未进行学习打卡（即当日无任何技能学习记录） |
| 衰减量 | 扣除 **6 小时** 进度（从累计小时数中扣减） |
| 衰减对象 | 对该用户下所有技能均扣除 6 小时 |
| 下限保护 | 单个技能累计小时数最低为 0，不可为负数 |
| 补签限制 | **不支持补签**，错过即扣除，不可事后补录 |

> **衰减执行时机**：每日凌晨 01:00（北京时间）执行检查，若前一日无学习记录（含草稿自动提交后仍无记录），则触发衰减。

### 4.5 技能树页面功能

| 功能项 | 说明 |
|--------|------|
| 技能列表 | 展示所有技能卡片，每张卡片含名称、进度条、当前阶段、累计小时数 |
| 创建技能 | 入口按钮 → 弹窗输入技能名称 → 生成进度条 |
| 技能详情 | 点击技能卡片 → 查看该技能的历史学习记录与阶段变化趋势 |
| 编辑技能 | 修改技能名称、描述（不影响累计进度） |
| 删除技能 | 删除后该技能的每日学习记录一并删除（需二次确认） |
| 排序方式 | 按创建时间 / 按累计小时数 / 按最近学习时间 |

## 5. 模块二：每日收获

### 5.1 打卡时间窗口

| 规则项 | 说明 |
|--------|------|
| 正式打卡时段 | 每晚 **23:00 ~ 次日 01:00**（北京时间，共 2 小时窗口） |
| 草稿编辑时段 | 任意时间均可进入打卡页面编辑内容并保存为草稿 |
| 时段外说明 | 非正式打卡时段进入页面时，提示「当前为草稿编辑模式，正式打卡时间为每晚 23:00 - 次日 01:00」 |
| 自动提交 | 若用户在正式打卡时段内未手动提交，系统将在次日 01:00 自动将草稿提交为正式打卡记录 |
| 当日唯一 | 每天只能有一条打卡记录，提交后仍可随时修改 |
| 修改限制 | **不限制修改次数**，已提交的打卡内容可随时编辑更新 |
| 补签限制 | 不支持补签历史日期的打卡 |

> **设计说明**：打卡时间窗口设定在每晚 23:00 - 次日 01:00，用户可在任意时间预先编辑草稿内容。非打卡时段保存的内容为草稿状态，进入正式打卡时段后用户可手动提交，也可继续编辑。若至次日 01:00 仍未手动提交，系统自动将已有草稿提交为正式记录。已提交的记录支持不限次数的修改。

### 5.2 学习进度录入

在打卡页面，用户需为每个技能录入今日学习时长：

| 规则项 | 说明 |
|--------|------|
| 录入对象 | 用户已创建的所有技能均出现在打卡列表中 |
| 录入方式 | 每个技能旁有输入框，输入今日学习小时数（可填 0） |
| 总和上限 | 所有技能今日学习小时数总和不超过 **8 小时** |
| 超限提示 | 总和超过 8 小时时禁止提交，提示「今日学习总时长不可超过 8 小时」 |
| 精度要求 | 最小精度 0.5 小时 |
| 联动更新 | 提交后各技能累计小时数即时增加，进度条与阶段同步刷新；修改打卡内容时，技能累计小时数同步增减 |

### 5.3 今日心得记录

| 功能项 | 说明 |
|--------|------|
| 文字记录 | 文本输入框，记录今日学习心得、收获、感悟（**必填**） |
| 图片记录 | 支持上传图片（截图、笔记照片等），单次打卡 **1~9 张**（**必填，至少 1 张**） |
| 图片限制 | 单张不超过 5MB，支持 jpg/png/jpeg/gif/webp 格式 |
| 文字限制 | 文字内容 **1~2000 字**（不可为空） |

### 5.4 标签管理

| 功能项 | 说明 |
|--------|------|
| 添加标签 | 对每日收获内容添加一个或多个标签（**必填，至少 1 个**） |
| 标签创建 | 用户可自由创建标签（如「突破」「瓶颈」「灵感」「复习」等） |
| 标签数量 | 单条收获 **1~5 个**标签（至少 1 个） |
| 标签管理 | 标签管理页可查看所有已创建标签，支持重命名与删除 |
| 标签颜色 | 创建时自动分配颜色或用户自选，便于视觉区分 |

### 5.5 标签筛选

| 功能项 | 说明 |
|--------|------|
| 筛选入口 | 收获列表页提供标签筛选区 |
| 筛选方式 | 点击标签进行筛选，支持多标签组合（AND 逻辑） |
| 清除筛选 | 一键清除所有筛选条件 |
| 结果展示 | 筛选结果按时间倒序排列 |

### 5.6 日/周/月视图

| 视图 | 展示内容 |
|------|---------|
| 日视图 | 按日期展示每日收获详情（学习时长、文字心得、图片、标签），一天一条 |
| 周视图 | 按周聚合展示，显示每周各技能学习时长统计、本周打卡天数、本周心得摘要 |
| 月视图 | 按月聚合展示，显示月度学习时长统计图表、月度打卡日历热力图、月度心得列表 |

**视图通用功能**：
- 时间导航：前后翻页切换日期/周/月
- 快捷跳转：跳转到今天/本周/本月
- 统计概览：每个视图顶部显示对应周期的总学习时长与打卡天数

## 6. 非功能需求

### 6.1 性能需求

| 指标 | 要求 |
|------|------|
| 页面首屏加载 | ≤ 2 秒 |
| 接口响应时间 | ≤ 500ms（常规接口） |
| 图片上传 | 单张 ≤ 3 秒完成上传 |
| 定时任务执行 | 每日凌晨 01:00 衰减任务在 5 分钟内完成全量执行 |

### 6.2 兼容性需求

| 端 | 要求 |
|----|------|
| 桌面浏览器 | Chrome 90+、Firefox 90+、Safari 14+、Edge 90+ |
| 移动浏览器 | iOS Safari 14+、Android Chrome 90+ |
| 响应式 | 适配桌面与移动端，最小宽度 320px |

### 6.3 数据安全

| 需求项 | 说明 |
|--------|------|
| 用户认证 | 基于 JWT 的认证方案 |
| 数据隔离 | 每个用户只能访问自己的技能与收获数据 |
| 图片存储 | 图片存储至对象存储服务（如 OSS），不直接入库 |
| 输入校验 | 后端对所有用户输入进行校验与转义，防 XSS |

## 7. 技术架构

### 7.1 整体架构

```
┌─────────────────────────────────────────────┐
│                   前端                        │
│            (React + TypeScript)              │
├─────────────────────────────────────────────┤
│  路由: React Router                           │
│  状态管理: Zustand / Context                  │
│  HTTP: Axios                                 │
│  UI: TailwindCSS + 组件库                     │
│  图表: ECharts / Recharts                     │
└─────────────────────────────────────────────┘
                      │
                      │ RESTful API (JSON)
                      ▼
┌─────────────────────────────────────────────┐
│                  后端                         │
│           (Node.js + NestJS)                 │
├─────────────────────────────────────────────┤
│  认证: JWT                                    │
│  ORM: Prisma / TypeORM                       │
│  定时任务: node-cron / @nestjs/schedule       │
│  文件上传: Multer → 对象存储                   │
└─────────────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────┐
│              数据库: PostgreSQL               │
│            对象存储: MinIO / OSS               │
└─────────────────────────────────────────────┘
```

### 7.2 前端技术选型

| 技术 | 用途 |
|------|------|
| React 18 | UI 框架 |
| TypeScript | 类型安全 |
| React Router | 路由管理 |
| Zustand | 轻量状态管理 |
| Axios | HTTP 请求 |
| TailwindCSS | 样式方案 |
| Framer Motion | 动效（苹果风流畅过渡动画） |
| Recharts / ECharts | 图表（进度可视化、统计视图） |
| dayjs | 日期处理 |

### 7.2.1 前端设计风格（Apple Design）

整体采用苹果设计风格（Apple Design / Human Interface Guidelines），核心原则：

| 设计要素 | 规范说明 |
|---------|---------|
| 色彩 | 以纯白/浅灰为主背景，黑色/深灰文字，强调高对比度与留白；主色调使用 SF Blue 系蓝色 |
| 排版 | 大标题 + 充足留白，字号层级分明，使用 SF Pro / -apple-system 字体族 |
| 卡片 | 圆角 12~16px，轻微阴影（box-shadow），背景使用毛玻璃效果（backdrop-filter: blur） |
| 动效 | 页面切换、卡片展开使用弹性过渡（ease-in-out, cubic-bezier），Framer Motion 驱动 |
| 进度条 | 圆角胶囊形，渐变色填充，支持平滑动画过渡 |
| 按钮 | 圆角胶囊形，主按钮使用蓝色填充，次按钮使用描边样式，hover 态有轻微缩放 |
| 弹窗 | 居中模态框，背景遮罩模糊，弹入弹出有缩放+淡入淡出动效 |
| 间距 | 模块间间距 32~48px，卡片内间距 16~24px，呼吸感强 |
| 暗色模式 | 支持暗色模式，背景 #1d1d1f，文字 #f5f5f7，遵循系统偏好自动切换 |

## 11. 核心业务流程

### 11.1 每日打卡流程

```
用户进入 /checkin
    │
    ├─ 后端判断当前时间
    │     ├─ 23:00 ~ 次日01:00（正式打卡时段）
    │     │     └─ 页面显示「正式打卡」状态，可保存草稿也可直接提交
    │     │
    │     └─ 其他时段（草稿编辑时段）
    │           └─ 页面显示「草稿编辑」状态，可编辑并保存草稿
    │              提示「正式打卡时间为每晚 23:00 - 次日 01:00」
    │
    ├─ 展示所有技能列表，逐个输入今日学习时长
    │     └─ 实时计算总和，超过 8h → 禁止提交
    │
    ├─ 填写文字心得（必填，1~2000字）
    ├─ 上传图片（必填，至少1张，最多9张）
    ├─ 添加标签（必填，至少1个，最多5个）
    │
    ├─ 草稿时段 → 保存草稿（status=draft）
    │     └─ 系统在次日01:00自动将草稿提交（status=submitted）
    │        并将学习时长同步至技能累计小时数
    │
    └─ 正式时段 → 手动提交（status=submitted）
         → 后端写入 DailyRecord + DailySkillLog + 更新 Skill.total_hours
         → 前端跳转收获列表

已提交记录的修改流程：
    └─ 用户可随时进入已提交记录 → 修改内容（文字/图片/标签/学习时长）
         → PUT /api/daily-records/:id → 后端更新记录
         → 若学习时长变化，同步增减 Skill.total_hours（不限修改次数）
```

### 11.2 每日衰减流程（定时任务）

```
@nestjs/schedule 每日凌晨 01:00 触发
    │
    ├─ 查询所有用户
    │
    ├─ 对每个用户：
    │     ├─ 首先执行草稿自动提交：
    │     │     └─ 若前一日存在 status=draft 的记录
    │     │           → 校验必填项完整性（文字/图片/标签）
    │     │           ├─ 完整 → 自动提交为 submitted，同步技能累计小时数
    │     │           └─ 不完整 → 草稿作废，视为当日未打卡
    │     │
    │     ├─ 检查前一日是否有 status=submitted 的 DailyRecord
    │     │     ├─ 有 → 跳过（已打卡）
    │     │     └─ 无 → 执行衰减
    │     │
    │     └─ 衰减执行：
    │           ├─ 该用户所有 Skill.total_hours -= 6
    │           ├─ 下限保护：total_hours 不低于 0
    │           └─ 写入 DecayLog 记录
    │
    └─ 任务完成
```

### 11.3 阶段判定逻辑

```
total_hours >= 600 → 精通
total_hours >= 300 → 熟练
total_hours >= 100 → 小成
total_hours >= 30  → 入门
total_hours < 30   → 未入门
```
